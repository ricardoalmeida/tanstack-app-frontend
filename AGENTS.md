# AGENTS.md

Guidance for agentic coding assistants working in this repository.

## Project Overview

TanStack Start (SSR) application using file-based routing, TanStack Query, Tailwind CSS v4,
and Storybook. Runtime: Bun. React 19 with the React Compiler enabled.

---

## Commands

```bash
# Development
bun dev                  # start dev server on http://localhost:3000

# Build & preview
bun run build            # production build
bun run preview          # preview production build

# Linting & formatting (Biome)
bun run lint             # lint only
bun run format           # format only
bun run check            # lint + format check (use this before committing)

# Testing (Vitest)
bun test                 # run all tests once
bunx vitest run src/path/to/file.test.tsx   # run a single test file
bunx vitest run --reporter=verbose          # verbose output for all tests
bunx vitest watch                           # watch mode

# Storybook
bun run storybook        # dev server on http://localhost:6006
bun run build-storybook  # static build

# Type checking
bunx tsc --noEmit        # type check without emitting
```

> `routeTree.gen.ts` is auto-generated by TanStack Router — never edit it manually.
> Re-runs automatically during `bun dev`; trigger manually with `bunx tsr generate`.

## Code Style

### Formatter & Linter — Biome

- **Indentation**: tabs (not spaces)
- **Quotes**: double quotes in JS/TS (`"value"`, not `'value'`)
- **Imports**: auto-organized by Biome (`assist.actions.source.organizeImports: on`)
- Run `bun run check` to validate before committing
- Biome config is in `biome.json`; `routeTree.gen.ts` and `styles.css` are excluded

### TypeScript

- Strict mode is fully enabled (`strict`, `noUnusedLocals`, `noUnusedParameters`,
  `noFallthroughCasesInSwitch`, `noUncheckedSideEffectImports`)
- Use `import type` for type-only imports — `verbatimModuleSyntax` is enforced
- Target: ES2022, module resolution: `bundler`
- Path aliases: both `@/*` and `#/*` resolve to `src/*`
  ```ts
  import { cn } from "@/lib/utils"
  import { env } from "#/env"
  ```
- Prefer `@/` for new code

### Naming Conventions

- **Components**: PascalCase (`UserCard`, `ThemeToggle`)
- **Files**: PascalCase for components (`Header.tsx`), camelCase for utilities (`utils.ts`)
- **Route files**: lowercase/kebab-case as required by TanStack Router (`__root.tsx`,
  `tanstack-query.tsx`)
- **Variables/functions**: camelCase
- **Constants**: camelCase (no ALL_CAPS unless truly global constants)
- **CSS classes**: kebab-case (`.island-shell`, `.nav-link`)

### Imports Order (Biome auto-organizes)

1. External packages
2. Internal aliases (`@/`, `#/`)
3. Relative imports

Always use `import type` for type-only imports:
```ts
import type { QueryClient } from "@tanstack/react-query"
import { useQuery } from "@tanstack/react-query"
```

## Routing

Uses TanStack Router with file-based routing. All routes live under `src/routes/`.

- `__root.tsx` — root layout (HTML shell, Header, Footer, providers, devtools)
- `index.tsx` — home route `/`
- `about.tsx` — `/about`
- `demo/*.tsx` — nested demo routes

Create routes with `createFileRoute`:
```ts
export const Route = createFileRoute("/my-page")({ component: MyPage })
```

Router context carries `QueryClient` — access it in loaders via `context.queryClient`.

## Styling

- **Tailwind CSS v4** — configured via Vite plugin (`@tailwindcss/vite`), no `tailwind.config.js`
- **Custom design tokens** live in `src/styles.css` under `:root` (light) and
  `[data-theme="dark"]` / `@media (prefers-color-scheme: dark)` selectors
- **shadcn CSS variables** (`--background`, `--foreground`, `--primary`, etc.) are defined in
  `styles.css` using `@theme inline` for Tailwind v4 compatibility
- **`cn()` utility** at `@/lib/utils` merges Tailwind classes safely:
  ```ts
  import { cn } from "@/lib/utils"
  className={cn("base-classes", conditional && "extra", className)}
  ```
- Reusable utility classes (not components): `.page-wrap`, `.island-shell`, `.feature-card`,
  `.island-kicker`, `.nav-link`, `.rise-in`

## UI Components

- shadcn-style components go in `src/components/ui/`
- Use `class-variance-authority` (CVA) for variant-based styling
- Use `@radix-ui/react-slot` for `asChild` prop pattern
- Add new components with the shadcn CLI:
  ```bash
  bunx shadcn add <component-name>
  # e.g.: bunx shadcn add card dialog input
  ```
- `components.json` at the repo root configures the CLI (style: new-york, cssVariables: true)

## Data Fetching

Uses TanStack Query. The `QueryClient` is instantiated in
`src/integrations/tanstack-query/root-provider.tsx` and injected into router context.

Prefer defining queries with `queryOptions()` for reusability:
```ts
import { queryOptions } from "@tanstack/react-query"
export const userQuery = (id: string) =>
  queryOptions({ queryKey: ["user", id], queryFn: () => fetchUser(id) })
```

## Environment Variables

Defined and validated in `src/env.ts` using `@t3-oss/env-core` + `zod`.

- Server-side vars: no prefix (e.g. `SERVER_URL`)
- Client-side vars: must be prefixed with `VITE_` (e.g. `VITE_APP_TITLE`)
- Always import from `@/env` — never read `import.meta.env` directly
- Add new vars to `src/env.ts` with a Zod schema
